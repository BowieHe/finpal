# FinPal 搜索优化研究计划

## 研究目标

优化 FinPal 的搜索策略，提升投资分析的信息质量和回答准确性。通过系统化实验找到最优的查询生成、结果筛选和搜索-辩论衔接策略。

## 可优化维度

### 1. 查询生成策略（Query Generation）

当前问题：
- 固定模板生成查询，没有针对不同场景的优化
- 查询数量和维度靠经验设定

可实验参数：
- 不同场景（基金分析、持仓回顾、市场新闻）的查询数量
- 查询模板结构
- 分析维度组合（净值、经理、行业、风险等）

### 2. 结果筛选策略（Result Filtering）

当前问题：
- 简单取前 8 条结果
- 没有去重和相关性排序

可实验参数：
- 结果数量（5/8/12/15）
- 去重阈值
- 时效性权重
- 来源多样性要求

### 3. 搜索-辩论衔接（Search-to-Debate Pipeline）

当前问题：
- 搜索结果直接汇总给 LLM 总结
- 没有针对 Bull/Bear 视角做信息预处理

可实验参数：
- 结构化提取 vs 自由总结
- 观点分离策略（标记乐观/悲观来源）
- 信息密度控制

## 评估指标体系

### 核心指标（权重 70%）

1. **回答质量分** (0-10)
   - 评估维度：准确性、深度、实用性、可解释性
   - 评估方式：LLM-as-a-judge

2. **信息相关性** (0-10)
   - 评估维度：搜索结果与用户问题的匹配度
   - 评估方式：LLM 评估 + 人工抽检

### 效率指标（权重 20%）

3. **响应时间** (ms)
   - 端到端搜索耗时
   - 目标：< 5s 平均响应

4. **Token 成本** (估算)
   - 搜索 + 总结的 token 消耗
   - 目标：降低 20% 以上

### 稳定性指标（权重 10%）

5. **一致性得分**
   - 相同问题多次运行的结果稳定性
   - 方差 < 10%

## 实验流程

```
1. 加载当前配置
2. 运行测试套件（20-30 个用例）
3. 计算综合指标
4. 与基线对比
   - 提升 > 5%：提交修改 (git commit)
   - 下降 > 10%：回滚 (git reset)
   - 其他：保留，继续实验
5. AI 提出下一个实验配置
6. 重复步骤 1-5
```

## 终止条件

- 连续 10 次实验无显著提升（< 5% 改进）
- 达到预设实验预算（50 次实验）
- 找到满意解（质量分 > 8.5 且响应 < 3s）

## 当前基线

- Query Config: 默认模板（2-3 个查询，基础维度）
- Filter Config: 取前 8 条结果
- 基线质量分: 待测量

## 实验记录规范

每次实验记录：
- 实验 ID（时间戳 + 序号）
- 修改的配置参数
- 完整的评估指标
- 与基线的对比
- Git commit hash（如果提交）

## 风险控制

- 每次只修改一个参数，便于归因
- 保留基线配置用于回滚
- 定期人工抽检评估质量
- 设置 API 调用预算上限
